## 冻结留出质量

[策略记录](./RETRIEVAL-DECISION-2.6.3.md) 在提交 6ba7c08 中先于留出评测冻结。36 条人工合成记忆、16 个训练查询、28 个独立留出查询（24 个正例、4 个无关问题）。真实 BGE q8、512 维，比较 BM25/语义/RRF/混合+图谱；Precision@5 固定除以 5。基线来自公开 memobox@2.6.2。

| 混合+图谱留出指标 | 2.6.2 | 2.6.3 候选 |
| --- | ---: | ---: |
| Recall@5 | 81.25% | 83.33% |
| Precision@5 | 20.83% | 21.67% |
| MRR@5 | 84.72% | 88.33% |
| 无关问题有结果率 | 50% | 50% |

每个正例的 Recall 均不低于基线；新版本 Recall/MRR 必须严格改善，Precision 不下降、无关召回不升高，否则 CI 拒绝。跨语言 ADB/API 卡顿语义漏项和无关问题误匹配仍存在，小型人工集不能推广为真实产品召回率；相似度也不证明事实当前有效。

## 实际磁盘与 MCP 性能

Windows x64、Bun 1.4.2/Node 24。公开 2.6.2 源码包与编译候选逐个串行测试；100/1000/10000 条临时磁盘记忆，25 次热查询及写入/并发采样（写入先热身 5 次）。端点模式使用真实 HTTP 与确定性稠密向量，隔离网络/排序开销；local 使用真实模型查询和固定合成文档的实际预计算向量。预置向量的导入计时不包含逐条模型补算。

| 10000 条，基线 → 候选 | 关键词 | HTTP 端点 | local |
| --- | ---: | ---: | ---: |
| 导入 ms | 30336 → 1868 | 30275 → 2628 | 30456 → 2585 |
| 初始化+首次查询 ms | 292 → 198 | 474 → 337 | 759 → 744 |
| 第一类热查询 P95 ms | 13.04 → 13.75 | 23.08 → 17.00 | 21.03 → 15.13 |
| 并发读写 P95 ms | 136.91 → 85.13 | 260.13 → 166.01 | 270.99 → 183.50 |
| 写入 P95 ms | 36.96 → 5.97 | 37.99 → 39.36 | 35.94 → 37.93 |
| 进程树峰值 MiB | 422 → 345 | 634 → 424 | 626 → 583 |

所有 9 场景达到原定门槛：热检索 P95 <50ms 且不超过基线×1.2+4ms；写入/并发不超过基线×1.3+8ms；冷延迟最多增加 200ms；峰值 <1GiB 且不超过基线×1.15+96MiB。固定预算吸收短操作调度及编译模型助手开销，不宣称每一项都加速。1000 条 local 峰值 255→297MiB，冷延迟 647→655ms；其写入 P95 11.04→7.97ms，并发 66.06→24.05ms。

重复 local 查询使用有界查询向量缓存；另外测量每次不同的真实模型查询，10000 条 P95 28.01ms，不能拿缓存成绩冒充模型推理。缓存不包含检索结果，范围及外部写入继续实时可见。内存读取真实 CLI/MCP 与模型后代；Windows 使用 OS 的进程生存期峰值之和，不保证各进程同时达到峰值。

定位优化：BM25 查询权重/有界倒排、实体候选、向量范数及快照复用；整批导入单事务避免逐条 fsync；Windows 模型助手启动消除约 3 秒进程创建等待；Float32 base64 IPC 减少大消息拆分；小模型单推理线程避免多 MCP 线程池竞争。分段跟踪中 SQLite 持久化通常 2–3ms，尖峰主要在模型/IPC 等待。100 次诊断采样单线程写入 P95 6.95ms；最终门禁使用上方独立全规模报告。78 段评测文本在线程调整前后向量逐位一致，[数值核对](./perf/thread-vectors-2.6.3.json)。线程行为参考 [ONNX Runtime 官方说明](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)。

## 真实旧库与客户端验收

通过只读连接对用户旧库创建副本，85 条内容及元数据的 SHA256 在补算前后均为 4ab9331179c13a5c6b1bc35ab1e319714473a8d3f189c9a51154b5cb34ace961。编译候选补算约 1301ms，85 条向量全部有效；两个 MCP 读取同一既有记忆并实际检索命中。原库未写入，正文、编号和凭据不进入提交或测试制品。

Claude Code/Codex/pi 实际模型完成保存与召回，三条合成标记进入同一临时库。pi 的一次模型调用进行了较多检索才保存，作为后续工具使用体验输入；该结果不证明每个 agent 会选择最短调用序列。测试使用临时用户目录，认证只在本机借用、用后删除，没有更改用户现有设置。

## 发行与回归

211 个测试、1058 项断言、类型检查及实际安装包通过。原平台为 Windows x64、Linux x64/arm64、macOS x64/arm64；真实 q8/端点检索、生成接线、Pi 扩展、维护/恢复、双 MCP、特殊路径和终止信号全部验收。

[完整 beta CI（4e37fc8）](https://github.com/bilbilmyc/memobox/actions/runs/38265380668) 15 项全绿；包含最终线程调整；正式版本在最新 PR/发行提交重新通过相同门禁。npm 入口约 12.6kB、0 生产依赖；Windows 程序 89374208 字节，gzip 41193714 字节。基础包不含可选 ML 依赖/权重。其余平台的体积与哈希由同一版本 manifest 给出。

main 发布复用完整 CI 验收的同一 tarball 和五个平台资产，不重新编译/打包；上传资产后核对下载字节，再 OIDC npm 发布，最后从公开 npm/GitHub 重新安装。详见 [自动发行](./AUTO-RELEASE.md)。正式 npm 入库及首次公开重装结果需以发布工作流为准。

复现质量与规模门禁：

```bash
bun install --frozen-lockfile --ignore-scripts
bun run prepublishOnly
node scripts/release/package.mjs pack-and-test
node scripts/run-acceptance.mjs artifacts/win32-x64/memobox.exe
# Linux/macOS 的独立程序没有 .exe 后缀
```

升级 lite 后执行 memobox model reindex；升级接线使用 memobox install <client> --force，并重启客户端。单条操作保持简洁；批量维护/覆盖恢复必须预览和明确确认。
