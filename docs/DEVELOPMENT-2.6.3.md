# memobox 2.6.3 开发记录

日期：2026-10-12。工作区版本 `2.6.3-dev.0`，尚未发布。npm latest 为已完成安装验收的 2.6.2。
原 2.7/2.8/2.9 的工作均归入 [统一路线](../ROADMAP.md)，本记录只报告实际实现和证据。

## 双重验收门槛

功能完整性与性能并列第一。逐条验收安装、配置、记忆维护、检索范围、诊断、备份恢复、共享、升级；同时测量冷启动、热检索、写入、补算、并发和内存。出现卡顿先定位，再决定自写算法或引入开源实现。算法评估包括召回质量、延迟、体积、许可证、维护成本。

保持 CLI + stdio MCP + SQLite，无新增生产依赖或常驻服务。真实模型、网络、CLI 启动和本地排序分别测量。功能没有闭环或关键性能回退未解决，不能宣称完整版本已交付。

| 能力 | 实际行为与验证 |
| --- | --- |

| MCP 维护 | 新增 `memory_get/update/forget/query`；严格参数 schema，结构化结果，错误不写入 |
| 范围检索 | CLI 与 MCP 的 kind/entity/source/since 条件按 AND 组合；在关键词、语义及图谱候选截断前过滤；项目使用已有实体标签 |

`embedding.model/dimensions/timeoutMs` 是端点模式设置；内置 lite 模式仍使用固定模型和维度。新配置需要重启 MCP，模型变化后执行 `model reindex`。Windows 原生程序及轻量 npm 入口已完成本地安装验收，无需外部 Bun；其余四个平台正在 CI 验收。正式发行物尚未发布。

## 性能优化与实测

定位并修复了三类重复开销：

- BM25 对每份文档重复计算查询词 IDF，并对无关文档评分。改为每个查询预计算 IDF，稀有词倒排表按需建立，最多缓存 128 个查询词；常见词自动选择全扫描。保持全库统计、实体子串和原文精确匹配。
- 图谱扩展每次从 SQLite 读全库并解析实体；每次保存又读取全部实体节点。改为实体倒排候选和只查询本条记忆的实体节点。
- 语义扫描重复计算已存向量范数，冷检索重复读取全库。缓存向量范数，两路冷缓存共用一次快照，向量点积使用独立热点函数及保持累加顺序的四维展开。

性能实验曾出现冷加载和热点回退，未保留这些方案。最终使用有界、按需索引；没有为了理论复杂度增加向量服务。

环境：Windows x64，Bun 1.4.2；100/1000/10000 条合成中文记忆，512 维确定性稠密向量，内存 SQLite，每种热查询连续采样 40 次。基线来自官方 registry 重新安装的 2.6.2；各版本在各自包目录下独立进程运行，避免源码别名混用。以下取最终稠密向量报告的 10000 条场景：

| 测量 | 2.6.2 | 当前开发版 |
| --- | ---: | ---: |
| 关键词稀有词检索 P95 | 2.61ms | 1.38ms |
| 关键词未命中检索 P95 | 18.51ms | 0.42ms |
| 混合稀有词检索 P95 | 9.80ms | 6.06ms |
| 混合常见词检索 P95 | 15.00ms | 11.85ms |
| 首次混合检索 | 141.23ms | 127.56ms |
| 首次关键词检索 | 91.53ms | 95.94ms |

首次关键词仍有约 4.4ms 的单次差异，不能声称所有场景都变快；后续要对冷启动重复采样并定位。这些数据包含本地检索和日志写入，不包含真实模型推理、网络、磁盘数据库、CLI 进程启动或下载。RSS 是累积进程快照，不是每个场景峰值，暂不据此宣称内存改善。

1000 个不同项目标签的补充写入测试：关键词批量导入从 652.63ms 到 404.42ms，混合从 577.12ms 到 366.65ms。主基准包含按需倒排与稠密向量，单一例子不能代替生产性能验收。

## 检索质量的当前证据

固定合成验收集包含 12 条记忆和 13 个查询，相关项由人工指定，涵盖中文、英文、实体子串、编号、符号、否定、历史冲突、近义改写、跨语言和无关查询。仅验证 BM25 与关键词+图谱，没有用模拟嵌入冒充真实模型质量。

| 指标 | 2.6.2 | 当前开发版 |
| --- | ---: | ---: |
| Recall@5（11 个有相关项的查询） | 72.7% | 81.8% |
| MRR@5 | 72.7% | 81.8% |
| Precision@5（固定 5 为分母） | 16.4% | 18.2% |
| 无关查询产生结果的比例（2 个查询） | 0% | 0% |

改善来自 ✅ 原文检索修复。近义改写和跨语言仍漏检；这两个路径需要真实嵌入模型及更大的独立留出集验收。历史冲突仍可能返回旧记忆，不能把关键词相似度当成“当前有效事实”。小样本指标不能推广为产品真实召回率。

## 本轮：检索解释、只读恢复预览和开发分支门禁

- CLI `search --explain` 与 MCP `memory_search { explain: true }` 共用实际排名和数据库快照，返回关键词/语义排名及分数、RRF 贡献、实体扩展标签。普通 JSON 数组保持兼容；解释不会多记一次检索日志。
- 模型请求失败、零查询向量、范围内无兼容向量和低于相似度门槛分别报告安全的原因码，不返回原始端点错误或凭据。融合与解释使用同一 RRF 贡献函数。
- `import <备份> --dry-run [--json]` 先验证整份备份，再用只读 SQLite 连接读取元数据；不存在的目标库视为空库，不建表/迁移/加载模型。预览区分新增、跳过、备份内重复编号及内容/元数据冲突；正式导入仍保留当前或首条同编号记忆。
- 开发使用 `codex/*` 分支。推送及面向 `main` 的 PR 执行 Windows/Linux 回归、类型检查、实际 tarball 安装及双 MCP 验证，产出可下载测试包；测试全绿且审查通过再合并。`AGENTS.md` 和双语 README 固化流程。开发版本不进入 npm latest。
- 本地 `bun run prepublishOnly`：199 测试、945 次断言，0 失败；类型检查通过。安装包约 65KB，验证包含显式解释、恢复预览、双进程修订及范围解释的真实命令/协议流程。原质量集 Recall@5/MRR 仍为 81.8%，未退化；该小样本不代表真实语义质量。
- 本轮仍只使用合成记忆和临时配置，没有改动用户真实数据库或客户端配置。只读预览显式 finalize 查询并关闭连接。
- Windows CI 的一次清理超时暴露了关闭连接后 prepared statement 仍保留文件句柄的问题。新增公开 `close()` 回归：保留 store 引用，立即删除临时数据库；旧实现稳定 EBUSY，`close(true)` 严格关闭并 finalize 后通过。移除共享/恢复测试清理中的全进程强制 GC，11 个共享回归连续 20 轮（220 测试、1000 断言）全部通过。未放宽 5000ms 功能测试超时。
- 普通检索按需跳过解释对象构建，避免额外热路径分配。单独重跑 10000 条、512 维稠密合成向量，与 npm 2.6.2 对照：关键词稀有词 P95 2.624→1.153ms，无匹配英文 16.548→0.310ms；混合常用词 14.851→11.266ms，稀有词 7.767→6.008ms。混合冷启动 149.475→138.136ms；关键词冷启动 98.745→106.550ms、含常用中文词的混合短语关键词查询 8.992→10.362ms 仍有退化，正式版前继续分析。RSS 仍是累计快照，不作为峰值结论。
- 原始记录：[本轮基线](./perf/branch-baseline-2.6.2-dense.json)、[本轮最终实现](./perf/branch-current-2.6.3-dense.json)、[解释前开发包对照](./perf/branch-before-explain-2.6.3-dense.json)。`explain-2.6.3-dense.json` 是与打包并行时的初次测量，供定位噪声使用，不能作为最终对照。

## 当前继续开发：诊断、维护与原生分发

- `doctor --json --strict` 只读检查旧库完整性、坏元数据、向量缺失/损坏/来源/维度；客户端路径采用显式配置和默认推断分别报告，不加载模型或迁移旧库。
- `maintain scan/plan/apply` 提供重复、潜在冲突、年龄候选和用户/agent 摘要合并；执行前备份，内容指纹拒绝过期计划，SQLite 事务与缓存提交保持一致。
- `restore --dry-run/--yes` 可恢复删除与合并前的内容、编号及创建时间；覆盖前再备份，其他编号不动。`import` 仍保留跳过已有编号的兼容行为。
- `install <client> --force` 先备份完整配置，再更新 memobox 接线；保留其他 agent、模型及用户设置。默认安装仍幂等。
- Windows 原生程序约 85.2 MiB、gzip 约 39.3 MiB；轻量 Node npm tarball 当前约 14 kB，无生产 npm 依赖。npm 主包按系统/CPU 下载 GitHub Releases 中的同版本平台压缩包，流式 SHA256 校验、原子缓存；不安装其他平台程序。
- 原生程序真实 `--lite` 已验证。编译程序解析磁盘模块的问题已复现；同一个程序通过内置运行时加载可选模型，模型助手随所属 CLI/MCP 退出，继续共用同一 SQLite 实现，无端口或共享模型服务。
- 本地实际安装包已验证中文/单引号路径、CLI 参数/退出码、批量维护/恢复、三家客户端生成配置、共享 MCP 和终止信号。五个平台 CI 与完整性能/留出集质量验收尚在进行，不能据此宣布正式版本完成。
